# Video Analysis and Generation via a Semantic Progress Function

**ArXiv ID:** 2604.22554  
**Submitted:** April 24, 2026  
**Authors:** Gal Metzer, Sagi Polaczek, Ali Mahdavi-Amiri, Raja Giryes, Daniel Cohen-Or

## Executive Summary

This paper introduces the Semantic Progress Function, a novel framework for analyzing and improving temporal consistency in video generation and analysis. Modern video generation models (diffusion models, autoregressive generators) often produce non-linear semantic evolution—long stretches of static content interrupted by abrupt jumps. The proposed semantic linearization procedure reparameterizes video sequences so that semantic content changes uniformly over time, resulting in smoother, more coherent videos. This model-agnostic approach is applicable to any generative model and significantly improves perceptual quality and temporal coherence.

## Problem Statement

### The Semantic Pacing Problem

**Observation:** When examining videos generated by state-of-the-art diffusion models or autoregressive generators, the semantic content exhibits non-linear evolution:

```
Frame 1-50: Scene setup (minimal change)
Frame 51-80: Gradual scene development
Frame 81-95: Rapid semantic shifts (objects appear/disappear abruptly)
Frame 96-100: Final state (static again)
```

This results in:
- **Temporal incoherence:** Viewers perceive jerky, unnatural transitions
- **Semantic jumps:** Content suddenly shifts without smooth progression
- **Reduced watchability:** Uneven pacing diminishes perceived quality
- **Training inefficiency:** Models waste capacity on static regions

### Prior Limitations

**Existing Video Generation Approaches:**
- Focus on frame-level quality and consistency
- Assume temporal consistency emerges from training
- Lack explicit mechanisms to control semantic pacing
- No quantitative framework to measure or correct temporal evolution

**Why This Matters:**
- Humans perceive smooth, linear semantic progression as more "natural"
- Video narratives and visual storytelling rely on controlled pacing
- Application domains (video editing, animation, content creation) require precise temporal control

### Research Gap

How can we quantify, analyze, and correct the semantic evolution of videos to achieve uniform temporal pacing? What framework enables post-hoc improvement of any video—generated or real—to enhance temporal coherence?

## Core Concepts & Theory

### Semantic Progress Function (SPF)

**Definition:** A one-dimensional function S(t) that captures cumulative semantic change from frame 0 to frame t:

```
S(t) = ∫₀ᵗ ||e(τ) - e(τ-1)|| dτ
```

Where:
- e(t): Semantic embedding of frame t (from a pre-trained model like CLIP)
- ||·||: L2 distance in embedding space
- S(0) = 0 (reference point)
- S(T) = total semantic change across video

**Interpretation:**
- Monotonically increasing curve from 0 to 1 (normalized)
- Slope indicates rate of semantic change
- **Ideal curve:** Linear (constant slope) → uniform semantic progression
- **Actual curve:** Often has steep and flat regions → non-uniform pacing

### Semantic Linearization

**Goal:** Reparameterize video so that S(t_new) = linear.

**Problem Formulation:**

Given original frame indices t ∈ [0, T] with semantic progress S(t), find mapping t_new(t) such that:
- S_new(t_new(t)) ≈ αt_new for some constant α
- Frames are retimed to achieve uniform semantic progression
- Temporal order is preserved (monotonic mapping)

**Solution Approach:**

1. Compute semantic embeddings for all frames
2. Calculate S(t) = cumulative sum of frame-to-frame distances
3. Define target linear curve: S_target(t) = αt
4. Find optimal retiming t_new → t that maps actual S to target linear S
5. Interpolate video to new frame times using optical flow or learned interpolation

### Mathematical Formulation

**Optimal Retime Mapping:**

```
t_new = T × (S(t) / S(T))
```

Maps actual cumulative progress S(t) to linear progress.

**Smoothness Constraint:**
- Avoid rapid frame skipping/duplication
- Use total variation minimization on t_new(t)
- Enforce: |dt_new/dt| should be smooth

**Energy Function:**

```
E = λ₁||S_target - S(t_new(t))||₂ + λ₂||∇²t_new||₂
```

Where:
- First term: Fit to target linear progress
- Second term: Smoothness of mapping
- λ₁, λ₂: Regularization weights

## Main Ideas & Contributions

### 1. Quantitative Temporal Coherence Metric

**Semantic Progress Linearity Score:**

```
Linearity = 1 - KL(S(t) || S_linear(t))
```

Measures deviation from linear progress:
- Score = 1.0: Perfect linear progression
- Score < 0.8: Noticeable non-linear pacing
- Enables benchmarking video generators by temporal coherence

### 2. Model-Agnostic Video Improvement

Unlike training-time improvements, semantic linearization:
- Works on any video (generated, real, or mixed)
- Requires no retraining of generation models
- Applicable post-hoc during inference
- Transferable across model architectures

### 3. Efficient Interpolation Strategy

**Frame Retiming Pipeline:**

```
Original Video
    ↓
Compute Semantic Embeddings (CLIP, etc.)
    ↓
Calculate Cumulative Progress S(t)
    ↓
Determine Optimal Retime Mapping t_new(t)
    ↓
Interpolate Frames using Optical Flow / DM
    ↓
Output: Linearized Video
```

**Interpolation Methods:**
- Optical flow-based frame interpolation (lightweight, fast)
- Diffusion-based interpolation (higher quality, slower)
- Hybrid: Use flow for small time gaps, diffusion for large gaps

### 4. Semantic Embedding Flexibility

Experiments with multiple semantic representations:
- **CLIP:** Vision-language embeddings (general)
- **DiT:** Diffusion Transformer features (generative)
- **DINO:** Self-supervised vision features (transferable)
- **Combinations:** Weighted ensemble of embeddings

Allows tuning of "semantics" based on task domain.

## Methodology & Implementation

### Algorithm Pseudocode

```python
def semantic_linearization(video_frames, embedding_model, 
                          lambda1=1.0, lambda2=0.1, max_iter=50):
    """
    Args:
        video_frames: List of T RGB images
        embedding_model: Pre-trained model (CLIP, DiNO, etc.)
        lambda1, lambda2: Regularization weights
    
    Returns:
        linearized_frames: Retimed video
        retime_map: t_new(t) mapping function
    """
    
    # Step 1: Extract semantic embeddings
    embeddings = [embedding_model(frame) for frame in video_frames]
    
    # Step 2: Compute semantic progress function
    diffs = [torch.norm(embeddings[i] - embeddings[i-1]) 
             for i in range(1, len(embeddings))]
    S = torch.cumsum(torch.tensor(diffs), dim=0)
    S = torch.cat([torch.tensor([0.0]), S])  # Prepend initial point
    S_normalized = S / S[-1]  # Normalize to [0, 1]
    
    # Step 3: Linear target curve
    t_linear = torch.linspace(0, 1, len(video_frames))
    
    # Step 4: Optimize retime mapping (total variation regularization)
    t_new = optimize_retime(S_normalized, t_linear, lambda1, lambda2, 
                           max_iter=max_iter)
    
    # Step 5: Interpolate frames to new timing
    interpolator = OpticalFlowInterpolator() or DiffusionInterpolator()
    linearized_frames = interpolator.interpolate(video_frames, t_new)
    
    return linearized_frames, t_new
```

### Computational Complexity

| Step | Complexity | Time (100 frames) |
|------|-----------|-----------------|
| Embedding Extraction | O(T) | ~30s (CLIP) |
| Progress Calculation | O(T) | ~0.1s |
| Retime Optimization | O(T²) | ~2s |
| Frame Interpolation | O(T) | ~60s (optical flow) |
| **Total** | O(T²) | **~92s** |

Practical: Real-time suitable for post-processing in typical video pipelines.

## Insights & Implications

### Fundamental Insights

1. **Semantic Pacing is Learnable:** Consistent patterns in how humans structure semantic progression suggests this is learnable/predictable

2. **Linearity ≠ Optimality:** While linear pacing is natural, some applications may benefit from non-linear semantic curves (e.g., dramatic tension with sudden reveals)

3. **Embedding Space Matters:** Choice of semantic embedding significantly affects results; no single "correct" embedding for all domains

4. **Generative Model Failure Mode:** Current generators fail to naturally produce linear semantic pacing—this is a systematic weakness worth addressing

### Broader Field Impact

- **New Evaluation Metric:** Semantic Progress Linearity score enables benchmarking of video quality beyond frame-level metrics
- **Bridge to Cinematography:** Connects computer vision research with film/animation industry best practices
- **Human-AI Collaboration:** Enables human directors to guide/correct AI-generated videos post-production

### Limitations & Open Questions

1. **Embedding Dependency:** Semantic linearization quality depends heavily on choice of embedding model

2. **Ambiguous Semantics:** Some videos intentionally have non-linear pacing (horror jump scares); framework can't distinguish intentional from unintentional

3. **Computational Cost:** While practical, full video linearization still takes ~90 seconds per 100-frame video

4. **Frame Interpolation Quality:** Limitations of optical flow and diffusion interpolation propagate to linearized output

5. **Generalization:** Trained on synthetic videos; real-world performance on diverse user-generated content uncertain

## Conclusion

The Semantic Progress Function provides an elegant, quantitative framework for understanding and improving temporal coherence in videos. By recognizing that viewers prefer smooth, linear semantic progression, this work bridges computer vision with principles from cinematography and narrative structure. The model-agnostic nature of semantic linearization makes it immediately applicable to improve outputs from any video generator, while the new temporal coherence metrics enable rigorous benchmarking of video quality. As video generation becomes increasingly prevalent, tools to ensure temporal coherence and natural pacing become essential for creating compelling visual content.
