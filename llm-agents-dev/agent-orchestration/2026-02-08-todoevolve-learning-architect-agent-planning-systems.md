# TodoEvolve: Learning to Architect Agent Planning Systems

**Authors:** Jiaxi Liu, Yanzuo Jiang, Guibin Zhang, Zihan Zhang, Heng Chang, Zhenfei Yin, Qibing Ren, Junchi Yan  
**ArXiv ID:** [2602.07839](https://arxiv.org/abs/2602.07839)  
**Published:** February 8, 2026  
**Subject Areas:** Computation and Language (cs.CL), Artificial Intelligence (cs.AI), Machine Learning (cs.LG)

## Executive Summary

Agent planning is fundamental to autonomous software development, yet current approaches rely on hand-engineered planning modules that don't adapt to task complexity. **TodoEvolve** introduces a meta-planning paradigm where a 14B model autonomously generates and refines task-specific planning architectures, trained via Impedance-Guided Preference Optimization (IGPO) to optimize for performance, stability, and token efficiency simultaneously. This work is transformative for agentic software development because it eliminates the need for manual orchestration tuning—agents can now self-improve their own planning strategies as they encounter new development scenarios, leading to cost-effective and adaptive multi-agent systems.

## Problem Statement

Planning architectures are critical for agent performance, yet their design remains largely manual and static:

- **Manual tuning burden:** Teams spend significant engineering effort on planning graphs (Chain-of-Thought, Tree-of-Thought, hierarchical decomposition)
- **One-size-fits-all limitation:** A single planning strategy rarely works across diverse tasks (simple bug fixes vs. large feature implementations)
- **Adaptation gap:** When agents encounter new problem types, planning strategies that worked before become suboptimal
- **Cost vs. quality trade-off:** More complex planning (deeper reasoning trees, broader exploration) improves correctness but increases token usage and latency
- **Theoretical gap:** What makes a planning strategy "good"? No principled approach to generate optimal planning topologies

For software development, this is acute: debugging a single-line fix requires different planning than implementing a complex algorithm. Current agents use the same planning for both, wasting tokens on simple tasks and under-planning on complex ones.

## Core Concepts & Theory

### The Planning Architecture Space

**PlanFactory** defines a modular design space for planning architectures with four dimensions:

#### 1. Topology
How thinking steps relate to action execution:
- **Sequential:** Think → Act → Think → Act (iterative refinement)
- **Hierarchical:** High-level planning → Mid-level task decomposition → Low-level execution
- **Parallel:** Multiple reasoning branches evaluated concurrently (debate/consensus)
- **Recursive:** Sub-planning for complex sub-tasks
- **Replan-on-Feedback:** Adapt plan based on execution results

#### 2. Initialization
How planning begins:
- **Direct:** Generate full plan upfront
- **Stepwise:** Plan one step at a time
- **Query-based:** Ask clarifying questions before planning
- **Experience-based:** Reference similar past tasks to seed initial plan

#### 3. Adaptation
How plans evolve during execution:
- **Static:** No changes to plan once started
- **Reactive:** Re-plan on error signals
- **Predictive:** Anticipate future hazards and adjust
- **Learning:** Extract lessons from execution and update meta-strategy

#### 4. Navigation
How to traverse the planning graph:
- **Greedy:** Always take highest-scoring next step
- **Beam Search:** Keep top-K candidates, prune low-probability branches
- **Backtracking:** Revert to previous states and try alternatives
- **Exploration Bonus:** Occasionally try low-probability steps for discovery

### Planning Architecture as Code

TodoEvolve represents planning architectures as **executable code**, not static prompts:

```python
# Example planning strategy generated by TodoEvolve
class DevelopmentPlan:
    def __init__(self, task):
        self.task = task
        self.complexity_estimate = self.estimate_complexity(task)
    
    def generate_plan(self):
        if self.complexity_estimate < 0.3:  # Simple task
            return self.simple_sequential_plan()
        elif self.complexity_estimate < 0.7:  # Medium task
            return self.hierarchical_plan_with_backtracking()
        else:  # Complex task
            return self.recursive_multipath_plan()
    
    def simple_sequential_plan(self):
        # Minimal reasoning, immediate action
        return [analyze_code, generate_fix, validate]
    
    def hierarchical_plan_with_backtracking(self):
        # Structured decomposition with recovery
        return [
            decompose_into_subtasks,
            [solve_subtask_1, solve_subtask_2],  # parallel
            merge_solutions,
            test_integrated_fix,
            if_failed: backtrack_and_replan
        ]
    
    def recursive_multipath_plan(self):
        # Deep reasoning with consensus
        return tree_of_thought(
            depth=4,
            branches_per_node=3,
            consensus_threshold=2/3
        )
```

### IGPO: Impedance-Guided Preference Optimization

TodoEvolve uses **IGPO**, a novel training objective combining three orthogonal preferences:

```
IGPO Loss = α₁ · Performance_Loss + α₂ · Stability_Loss + α₃ · Efficiency_Loss

Performance_Loss: 
  Maximize task success rate
  Minimize steps-to-solution

Stability_Loss:
  Penalize high variance across repeated runs
  Encourage consistent, deterministic planning

Efficiency_Loss:
  Minimize token usage
  Penalize redundant reasoning steps
```

**Why multi-objective?** Single-objective optimization creates pathological strategies:
- Optimizing performance alone → infinite-depth reasoning trees
- Optimizing efficiency alone → oversimplified plans that fail
- IGPO balances these tensions, producing **Pareto-optimal** planning strategies

## Main Ideas & Contributions

### 1. Meta-Planning: Planning that Plans

**Key insight:** Planning architecture is itself a learnable skill

- TodoEvolve treats planning strategy selection as a learned policy
- Given a task description, predict which planning topology will work best
- Learn jointly with task execution (meta-learning loop)

**Benefits over static approaches:**

| Dimension | Static Planning | TodoEvolve Meta-Planning |
|-----------|-----------------|-------------------------|
| Adaptation | None; same plan for all tasks | Customized per task |
| Token efficiency | High variance; wastes on easy tasks | Balanced across difficulties |
| Performance | Limited by single best strategy | Potentially optimal per task |
| Engineering cost | Manual for each domain | Learned automatically |

### 2. PlanFactory: Unified Planning Specification

**Key innovation:** All planning paradigms (CoT, ToT, HiP) expressed in same formalism

- Topology: DAG structure of thinking/action steps
- Initialization: Seed prompts and prior knowledge
- Adaptation: Update rules and trigger conditions
- Navigation: Search strategy over planning graph

This unification enables:
- Comparing planning strategies fairly (same evaluation framework)
- Composing strategies (e.g., hierarchical + parallel)
- Evolving strategies (mutations and crossover in architecture space)

### 3. Token-Efficient Reasoning

**Challenge:** Complex tasks often need deep planning, but this multiplies token cost

**Solution:** TodoEvolve learns task-dependent planning depth

```
Example: GitHub Issue Fixing
├── Simple (typo fix): 50 tokens → accuracy 95%
├── Medium (logic bug): 200 tokens → accuracy 92%
└── Complex (architecture): 500 tokens → accuracy 88%

vs. Static strategy using 500 tokens for all:
├── Simple: 500 tokens → accuracy 96% (wasted 450 tokens)
├── Medium: 500 tokens → accuracy 93% (ok)
└── Complex: 500 tokens → accuracy 88% (insufficient)

TodoEvolve learns to allocate tokens where they matter most.
```

### 4. Multi-Agent Orchestration Implications

TodoEvolve planning strategies are composable with multi-agent frameworks:
- Each agent can have its own generated planning strategy
- Hierarchical agents can dynamically adjust sub-agent planning
- Skill-based agents can select plans matching their specialization

## Methodology & Implementation

### Training Setup

**Model:** Todo-14B (specialized planning model based on Qwen)

**Training Data:**
- Source: Diverse agentic tasks across five benchmarks
- Each task annotated with: expected complexity, optimal solution path, failure modes
- Synthetic variants: tasks mutated to test plan generalization
- Mix: ~60% real tasks, ~40% synthetic variations

**Preference Learning:**

```
For each task with planning strategy p:
1. Generate alternative plans p₁, p₂, p₃ (variations)
2. Execute all plans (measure performance, stability, efficiency)
3. Rank preferences: which plan best balances three objectives
4. Optimize IGPO to match preference ordering
```

### Benchmarks Evaluated

**Five agentic task benchmarks:**

1. **WebShop:** E-commerce task completion (navigation, reasoning)
2. **Tool Manipulation:** Multi-step tool use with dependency tracking
3. **Code Generation:** Writing functions meeting specifications
4. **Autonomous Debugging:** Locating and fixing bugs
5. **Repository-Level Tasks:** Full-project software engineering

Each benchmark includes:
- Task complexity labels (estimated)
- Baseline planning strategies (manual)
- Performance ground truth

### Metrics

| Metric | Definition | Relevance |
|--------|-----------|-----------|
| Success Rate | % tasks completed correctly | Primary quality signal |
| Stability | Consistency across 5 random seeds | Production readiness |
| Token Efficiency | Avg. tokens to solve (lower is better) | Cost optimization |
| Plan Diversity | How different are generated plans | Generalization signal |
| Adaptation Speed | Performance on out-of-distribution tasks | Robustness |

**Key Results Summary:**

1. **Overall superiority:** TodoEvolve consistently outperforms hand-engineered baselines across all five benchmarks
2. **Token efficiency:** TodoEvolve achieves 30-40% lower token usage vs. fixed deep-reasoning strategies while maintaining or improving accuracy
3. **Stability:** Generated plans show lower variance across runs than typical Chain-of-Thought strategies
4. **Scalability:** Performance improves with model scale; Todo-14B > Todo-7B > baselines
5. **Generalization:** Plans generated on one benchmark partially transfer to others (suggesting learned principles)

### Ablation Studies

Key components validated:
- **IGPO necessity:** Single-objective optimization produces worse plans than IGPO
- **PlanFactory expressiveness:** Simpler planning languages (e.g., tree-depth only) underperform
- **Meta-learning loop:** Jointly training planning strategy and execution outperforms pipeline approach

## Practical Applications & Use Cases

### Software Development Automation

**Scenario: Multi-file refactoring**

```
Developer task: "Refactor authentication system to support OAuth"

TodoEvolve analysis:
- Task complexity: 0.85 (high)
- Components affected: 12 files
- Risk level: Medium (wide impact, clear scope)

Generated plan:
1. Hierarchical decomposition (break into 4 sub-modules)
2. Parallel analysis of each module
3. Design phase with backtracking (try 2 approaches, pick best)
4. Sequential implementation (dependencies between modules)
5. Integration testing with reactive replanning

Estimated tokens: 450 (vs. 600 for fixed deep reasoning)
Estimated time: 12 hours of agent computation (vs. 16 hours fixed)
Success probability: 87% (vs. 82% fixed strategy)
```

### Autonomous Testing

**Scenario: Generating comprehensive test suite**

TodoEvolve would select hierarchical + parallel planning:
- Analyze code structure in parallel (multiple modules)
- Hierarchically decompose by test types (unit, integration, E2E)
- Sequential generation respecting dependencies
- Reactive replanning if coverage gaps detected

### Code Review Automation

**Scenario: Reviewing 50-file pull request**

TodoEvolve might generate:
- High-level issue detection (quick scan)
- Deep analysis of risky areas (authentication, data access)
- Consensus-based final recommendations (if multiple approaches identify same issue)
- Adaptive follow-up questions based on review findings

## Insights & Implications

### For Agentic Software Development

1. **Planning architecture matters immensely:** A good plan beats raw capability; TodoEvolve shows planning is learnable
2. **Task-adaptive strategies are essential:** One-size-fits-all planning wastes resources and/or misses edge cases
3. **Token efficiency is achievable without accuracy loss:** By allocating reasoning where it helps most, TodoEvolve cuts costs 30-40%
4. **Meta-learning speeds up agent improvement:** Rather than hand-tune strategies, let agents learn what works

### For Multi-Agent System Design

1. **Composable planning strategies:** Hierarchical agents can be composed using learned planning at each level
2. **Skill specialization:** Different agent types (testing agents, refactoring agents) can be trained with task-specific planning
3. **Runtime optimization:** Plan selection can be dynamic, changing based on agent state and task features
4. **Cost-benefit trade-offs:** Explicit IGPO objective captures the classic tension between accuracy and efficiency

### Limitations & Open Questions

1. **Generalization limits:** Generated plans are somewhat task-specific; transferability to new domains is incomplete
2. **Explainability:** Why does TodoEvolve choose a particular plan? Hard to interpret learned strategies
3. **Scaling beyond 14B:** Does the approach hold for smaller or larger models?
4. **Human validation:** Do generated plans match developer intuition? (Paper doesn't address this)
