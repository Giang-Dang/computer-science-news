## Executive Summary

StepPO presents a principled argument—and preliminary evidence—that **agentic reinforcement learning should operate at the *step* level rather than the *token* level**. Current RL methods for LLM agents (RLHF, GRPO, PPO) formulate the MDP at the token level, even though agents make meaningful decisions at the granularity of *actions* (tool calls, search queries, code executions). StepPO proposes step-level credit assignment as the natural optimization counterpart for this step-level MDP formulation, with a key insight: aligning reward propagation with the granularity of agent decisions produces better policies for multi-turn interactive tasks than token-level RL, while also addressing sparse and delayed reward challenges.

---

## Problem Statement

Modern LLM agents—systems like Claude Code, OpenClaw, software engineers, and research assistants—operate in multi-turn interactive environments. An agent:
1. Receives a task (e.g., "Fix bug X in this repository")
2. Takes a sequence of *steps* (read file, run test, edit code, run test again, ...)
3. Eventually produces a final outcome (task success or failure)

**The mismatch between RL formulation and agent behavior:**

Standard RL for LLMs (RLHF, GRPO) models the decision process at the **token level**: every individual token generated by the LLM is treated as an "action" in the MDP, and rewards are propagated from the final outcome back through every token. This creates severe problems:

1. **Credit assignment**: When the agent generates 10,000 tokens across 20 steps, which tokens were responsible for the final reward? Token-level credit assignment is computationally intractable and practically meaningless for most tokens.

2. **Misaligned granularity**: The agent's meaningful decisions happen at the *step* level (should I run a search or execute code?), not at the token level (should this token be "the" vs "a"?). Optimizing at the token level misaligns the optimizer with the decision-maker.

3. **Long context challenges**: Agentic trajectories have variable and often very long contexts, making token-level value estimation (needed for PPO) particularly unreliable.

## Core Concepts & Theory

### The Step-Level MDP Formulation

StepPO argues that the natural formulation for agentic RL is a **step-level MDP**:

```
State s_t = (task description, action history {a_1, ..., a_{t-1}}, 
             observations {o_1, ..., o_{t-1}}, current context)

Action a_t = a complete agent step:
           - Tool call: "search_web('query')"
           - Code execution: "run_python(script)"  
           - Message/plan: "I should first check..."

Transition T(s_{t+1} | s_t, a_t) = environment response (search results, 
                                    code output, error message, ...)

Reward R(s_t, a_t) = typically sparse (0 until task completion, then ±1)
```

Each "action" in this MDP corresponds to a complete agent step—not an individual token.

### Token-Level vs. Step-Level Credit Assignment

**Token-level (standard RL):**
```
For trajectory {token_1, ..., token_10000}, final reward R:

gradient ∝ Σ_t (R - V(s_t)) · ∇_θ log π_θ(token_t | s_t)
```

This treats every token equally important for gradient computation, which is both computationally expensive and semantically wrong (most tokens within a step don't represent decisions).

**Step-level (StepPO):**
```
For trajectory {step_1, ..., step_N}, reward possibly per-step R_t:

gradient ∝ Σ_t (R_t - V(s_t)) · ∇_θ log π_θ(step_t | s_t)
           where "step_t" = the full sequence of tokens in that step
```

By treating each step as the atomic action unit, gradients are assigned to meaningful decision points rather than individual tokens.

### Step-Level Policy Gradient

The StepPO objective is:

```
L_StepPO(θ) = -E_{τ~π_θ}[Σ_{t=1}^{N} A_t^step · log π_θ(a_t | s_t)]
             + β · Σ_t KL[π_θ(· | s_t) || π_ref(· | s_t)]
```

Where:
- `A_t^step = R_t - V_step(s_t)` is the step-level advantage
- `V_step` is a step-level value function (much easier to learn than token-level)
- The KL term prevents the policy from diverging too far from the reference

### Step-Level Reward Propagation

A key design choice in StepPO is how to assign rewards to individual steps when only a final outcome reward is observed. The paper proposes several strategies:

1. **Uniform propagation**: `R_t = R_final / N` for all steps — simple baseline
2. **Discounted propagation**: `R_t = γ^{N-t} · R_final` — steps closer to success get more credit
3. **Learned step rewards**: A step-level reward model that estimates contribution of each step — most powerful but requires training data

## Main Ideas & Key Contributions

### 1. The Step as the Proper Action Representation

The paper's central conceptual contribution is arguing—with both theoretical justification and empirical evidence—that the *step* (not the token) is the proper action abstraction for LLM agents. This reframing has implications for architecture, training, and evaluation of agentic systems.

### 2. Step-Level Credit Assignment

A concrete algorithm for assigning credit (reward signal) to individual steps within a trajectory, enabling meaningful policy gradient computation for multi-turn agents.

### 3. Systems Design for Step-Level Agentic RL

The paper discusses the engineering infrastructure required to implement step-level RL at scale:
- **Step boundary detection**: Automatically identifying where one step ends and the next begins
- **Environment parallelism**: Running many trajectories in parallel for RL sampling
- **Variable-length sequence handling**: Step sequences have different token lengths; efficient batching requires careful implementation

### 4. Preliminary Empirical Validation

Initial experiments provide evidence that step-level policy optimization outperforms token-level approaches on multi-turn agent benchmarks, with the advantage growing as task length increases.

## Methodology & Implementation

### Experimental Setup

- **Tasks**: Multi-turn agent benchmarks: ALFWorld (household tasks), WebArena (web navigation), SWE-Bench (software engineering)
- **Base models**: 7B-70B parameter LLMs
- **Baselines**: PPO (token-level), GRPO (token-level), SFT+prompting

### Architecture for Step-Level Value Estimation

The step-level value function `V_step(s_t)` is a smaller model (e.g., a 1B parameter model) trained to predict the probability that the current trajectory will succeed given the current state. This is significantly easier to train than token-level value functions because:
- Input is the current *state summary* (compact representation of what's happened so far)
- Output is a scalar probability
- Training signal: whether the trajectory succeeded (binary)

### Key Implementation Details

```python
# Pseudocode for step-level trajectory collection
def collect_trajectory(agent, env, task):
    state = env.reset(task)
    steps = []
    
    while not done:
        step_tokens = agent.generate_step(state)  # full step as text
        new_state, reward, done = env.step(parse_action(step_tokens))
        steps.append((state, step_tokens, reward))
        state = new_state
    
    # Assign step-level advantages
    advantages = compute_step_advantages(steps, value_fn)
    return steps, advantages

# StepPO gradient computation
def steppo_loss(steps, advantages):
    loss = 0
    for (state, step_tokens, _), adv in zip(steps, advantages):
        # log probability of entire step (all tokens)
        log_prob = sum(log_p(token | prev_tokens) 
                      for token in step_tokens)
        loss -= adv * log_prob  # policy gradient
    return loss
```

## Practical Applications & Real-World Use Cases

### 1. Software Engineering Agents

Systems like Claude Code, SWE-agent, and Devin that autonomously write, debug, and test code operate over long multi-step trajectories. StepPO's step-level RL is directly applicable to improving these systems, especially for complex, multi-file bugs that require many steps to resolve.

### 2. Research Assistants

AI research assistants that iteratively search literature, extract information, form hypotheses, and design experiments make decisions at the step level. StepPO would enable RL-based training of such agents with appropriate credit assignment.

### 3. Browser and Computer-Use Agents

Agents that control web browsers or computers (clicking, typing, navigating) take clear step-level actions. StepPO's formulation maps naturally to these settings, where each UI interaction is a step.

### 4. Healthcare AI Agents

Clinical decision support agents that review patient history, order tests, interpret results, and recommend treatments need fine-grained credit assignment (which diagnostic step was most valuable?). StepPO provides the framework for training such systems.

## Insights & Implications

### Why Granularity Matters in RL

StepPO makes a general point about RL that extends beyond LLMs: **the choice of action abstraction level significantly affects learning efficiency**. In classical RL, this is known as the *temporal abstraction* or *options framework* problem. StepPO can be seen as applying temporal abstraction principles to LLM training.

### Connection to Process Reward Models

Step-level RL is closely related to *process reward models* (PRMs) that provide intermediate feedback on reasoning steps. StepPO provides the optimization algorithm (policy gradient) to complement PRMs, which provide the reward signal.

### The Agentic RL Frontier

StepPO represents the state of the art in a rapidly evolving field. As LLM agents become more capable and are deployed in increasingly complex tasks, the training paradigm must evolve from single-turn RLHF to multi-turn agentic RL. StepPO contributes one key piece: how to do credit assignment correctly.

### Limitations

- **Preliminary results**: The paper explicitly describes its experimental results as "preliminary evidence"—more comprehensive benchmarking is needed
- **Step boundary definition**: Automatically detecting step boundaries in free-form agent outputs is non-trivial
- **Reward sparsity**: Even with step-level formulation, rewards remain sparse for many tasks
