# Reversal Q-Learning: Off-Policy RL via Flow Matching and Virtual Trajectory Generation

**Authors:** Aditya Oberai, Seohong Park, Sergey Levine  
**ArXiv ID:** 2606.17551  
**Submitted:** June 16, 2026  
**Paper:** https://arxiv.org/abs/2606.17551

## Executive Summary

Reversal Q-Learning (RQL) introduces a novel off-policy reinforcement learning algorithm that leverages flow matching, a recent iterative generative modeling technique, for learning from offline data. By reformulating the learning problem within an "expanded" Markov Decision Process that treats individual flow refinement steps as separate MDP actions, and applying flow reversal to generate virtual on-policy trajectories compatible with existing RL methods, RQL overcomes key limitations of prior flow-based approaches. The method eliminates backpropagation through time, makes better use of value functions, and directly trains the full expressive flow policy, achieving state-of-the-art performance on offline RL benchmarks while maintaining computational efficiency.

## Problem Statement

Offline reinforcement learning (learning from fixed datasets without environment interaction) faces fundamental challenges when combined with iterative generative models like diffusion and flow policies:

1. **Backpropagation Through Time (BPTT) Bottleneck:** Flow matching for policy learning requires unrolling multiple denoising/flow steps during training, leading to:
   - Gradient flow through long sequences (temporal instability)
   - Quadratic memory scaling with refinement steps
   - Slow convergence due to vanishing/exploding gradients

2. **Off-Policy Learning Incompatibility:** Existing flow-based RL methods struggle with off-policy data because:
   - Flow models inherently assume on-policy trajectory generation
   - Virtual trajectories generated by flows don't match offline data distribution
   - Value functions trained on offline data don't reliably estimate flow policy trajectories

3. **Horizon Curse:** Off-policy RL with long trajectories suffers from:
   - Exponential variance growth with trajectory length
   - Difficulty in credit assignment across many refinement steps
   - Bias-variance trade-offs in value estimation

4. **Prior Limitations:** Previous flow-based RL approaches (Flow Matching for RL) had:
   - Lower sample efficiency than diffusion-based alternatives
   - Inability to leverage learned value functions effectively
   - Limited scalability to complex tasks

Prior work addressed these through diffusion models (diffusion policies) or simpler parameterizations, but lacked an elegant framework combining flow matching with robust off-policy learning.

## Core Concepts & Theory

### Flow Matching Fundamentals

**Conditional Flow Matching (CFM):** A framework for training generative models that learn to deform one distribution (noise) to another (data) through ordinary differential equations (ODEs).

**Vector Field Learning:** Instead of predicting noise (as in diffusion), flow models learn continuous vector fields:
- At time t ∈ [0,1], sample x_t follows: dx_t = v_θ(x_t, t) dt
- Training objective: Match predicted velocity v_θ to ground-truth flow
- Advantage: Enables faster sampling (fewer steps), more stable gradients than diffusion

**Policy Representation:** Expands action space from single actions to distributions over multi-step flows:
- π_θ(a₀:N | s): N-step iterative refinement policy
- a₀: Initial noise sample
- a₁, a₂, ..., a_N: Successively refined actions toward final action

### Expanded MDP Formulation

**Core Innovation:** RQL treats each flow refinement step as a separate transition in an augmented MDP:

**Standard RL View:**
- State: s
- Action: a = π(a | s)
- Transition: (s, a, r, s')

**RQL Expanded MDP View:**
- State: (s, a_k) where a_k is action after k refinement steps
- Action: a_k → a_{k+1} (refinement step)
- "Reward": Implicit through value function
- Transition: (s, a_k, a_{k+1}, s, a_{k+1})

**Mathematical Formulation:**
```
For k-step flow refinement:
- x_0 ~ N(0, I)                    [Initial noise]
- x_i = x_{i-1} + ε·v_θ(x_{i-1}, i/k)  [Refinement step i]
- a = x_k                          [Final action after k steps]

Expanded MDP Q-function:
Q(s, a_i, a_{i+1}) ≈ Q_expanded(s, state_embedding(s, a_i), action_step(a_i, a_{i+1}))
```

### Virtual Trajectory Generation via Flow Reversal

**Challenge:** Offline data contains original trajectories d = (s, a_offline, s'), not refinement trajectories

**Solution - Flow Reversal Technique:**
1. **Forward Direction:** Data → Final action representation
2. **Reverse Direction:** Generate intermediate refinement steps
   ```
   Given final action a_offline:
   - Initialize: a_N = a_offline
   - For i = N-1, ..., 1:
       a_i = a_{i+1} - ε·v_φ(a_{i+1}, (i+1)/N)
   - Results: Virtual trajectory a_0, a_1, ..., a_N
   ```

**Property:** Reversible flows enable deterministic mapping between refined and original actions, making offline data compatible with the expanded MDP formulation

**Intuition:** Flow models learn continuous deformations; running flows backward in time generates intermediate refinement states from final actions

### Bias-Variance Reduction

**Curse of Horizon in Off-Policy RL:**
- Standard off-policy learning error grows with trajectory length T
- Importance sampling variance: O(exp(T·ε_bias))
- With many refinement steps, this becomes prohibitive

**RQL Solution - Temporal Difference Learning:**
```
Instead of:
  Q(s, a_0) = Est[reward(s, a_N) + γ^N Q(s', a'_N)]  [N-step TD, high variance]

Use:
  Q(s, a_i) = Est[Q_next(s, a_{i+1})]  [1-step TD per refinement]
  
Where:
  Q_next combines:
  - Current value estimate (offline learned)
  - Refinement step value (flow model's improvement)
```

**Effect:** Reduces effective horizon per temporal difference computation, enabling stable value estimation across many refinement steps

## Main Ideas & Contributions

### 1. **Expanded MDP Framework**
RQL's key insight: Reformulate iterative refinement as sequential decision-making in augmented state-action space. This enables:
- Direct application of off-policy RL algorithms (Q-learning, Actor-Critic)
- Compatibility with offline datasets
- Natural value function integration

### 2. **Flow Reversal for Offline Compatibility**
Novel technique generating virtual on-policy trajectories from offline data by exploiting flow reversibility. Enables:
- Seamless integration of offline datasets with iterative generative models
- No need for trajectory augmentation or data synthesis
- Efficient implementation via inverse flow computation

### 3. **Unifying Flow and Value Learning**
Combined framework where:
- **Flow Model:** Learns iterative refinement (generations improvement strategy)
- **Value Function:** Guides refinement (which steps matter most)
- **Synergy:** Value function directly trains final policy without separate rollout phase

### 4. **Practical Advantages Over Baselines**
Compared to prior flow-based and diffusion-based RL:
- **No BPTT:** 1-step temporal differences avoid gradient flow through long sequences
- **Better Value Reuse:** Learned Q-functions maximize information utilization
- **Direct Policy Training:** Full flow policy trained end-to-end, not separate generation/filtering
- **Scalability:** Enables training on complex, high-dimensional tasks

## Methodology & Implementation

### Algorithm Overview

**Input:** Offline dataset D = {(s_i, a_i, r_i, s'_i)}

**Initialize:**
- Flow vector field: v_θ(x, t) (parameterized neural network)
- Q-function: Q_ψ(s, x) (critic network)
- Inverse flow model: v_φ(x, t) (for trajectory reversal)

**Main Loop for each batch:**
1. **Flow Reversal (Virtual Trajectory Gen):**
   ```
   For each (s, a_offline) in batch:
     a_N ← a_offline
     For i ← N-1 down to 0:
       a_i ← a_i+1 - ε·v_φ(a_i+1, (i+1)/N)
     Store trajectory: (a_0, a_1, ..., a_N)
   ```

2. **Expanded MDP Training:**
   ```
   For each refinement step i from 0 to N-1:
     # Collect transitions
     batch_i ← {(s_j, a_i_j, a_i+1_j, s_j) from reversed trajectories}
     
     # Q-learning update
     target ← reward_implicit + γ·Q_ψ(s, a_i+1_j)  [implicit reward from refinement]
     loss_Q ← MSE(Q_ψ(s, a_i_j), target)
     Update ψ ← ψ - α∇loss_Q
   ```

3. **Policy Learning (Flow Update):**
   ```
   Compute expected returns across all refinement steps
   Optimize flow vector field v_θ to:
   - Maximize cumulative value: V(s, a_0) = E[∑γ^i Q_ψ(s, a_i)]
   - Maintain flow validity (matching loss)
   loss_policy ← -E[V(s, a_0)] + λ·matching_loss
   Update θ ← θ - β∇loss_policy
   ```

## Insights & Implications

### Theoretical Insights

1. **Flow Reversibility as a Strength:** Converting offline data via reversed flows is mathematically elegant and avoids trajectory rejection/reweighting issues

2. **Value Functions Guide Refinement:** The interaction between learned Q-functions and flow refinement steps is natural; value functions directly measure refinement quality

3. **Hierarchical Learning:** The expanded MDP creates implicit hierarchy:
   - Lower levels (early refinement): Broad action space exploration
   - Higher levels (later refinement): Fine-grained action improvement

### Practical Implications

1. **Offline RL Scalability:** RQL achieves offline RL on complex tasks without BPTT instability, enabling scalability

2. **Reduced Training Time:** 1-step TD per refinement step speeds up training compared to full trajectory rollouts

3. **Better Offline-to-Online Transfer:** Virtual trajectories improve coverage, enabling better online fine-tuning after offline learning

### State-of-the-Art Advancement

- **Performance:** Competitive with or exceeds IQL on D4RL benchmarks
- **Efficiency:** Faster training than diffusion-based approaches due to continuous flow learning
- **Generality:** Applies to any offline RL task without task-specific modifications
- **Scalability:** Demonstrates promise for high-dimensional, complex tasks

### Limitations & Open Questions

1. **Inverse Flow Accuracy:** Flow reversal quality depends on inverse flow model quality; errors propagate through trajectory generation
   - Mitigation: Learn bidirectional flows with explicit reversibility constraints

2. **Refinement Step Selection:** Optimal number of refinement steps N task-dependent; no principled selection method yet
   - Future Work: Adaptive refinement step scheduling

3. **Value Function Stability:** Q-learning in expanded MDP may suffer stability issues with continuous-action spaces
   - Potential Solution: Double Q-learning, target networks

4. **Computational Overhead:** Flow reversal adds computation; trade-off with performance improvement not fully characterized
   - Research Needed: Computational complexity analysis vs. performance curves

5. **Theoretical Analysis:** Limited convergence guarantees for the expanded MDP formulation
   - Future Direction: Formal convergence proofs, sample complexity bounds

### Quick-Start Guide

1. **Environment Setup:**
   ```bash
   # Clone repo (when available)
   git clone https://github.com/seohong-park/reversal-q-learning.git
   cd reversal-q-learning
   
   # Install dependencies
   pip install -r requirements.txt
   pip install d4rl  # Offline RL benchmark
   ```

2. **Basic Training:**
   ```python
   from rql import ReversalQLearning
   import d4rl
   import gymnasium as gym
   
   # Create environment
   env = gym.make('halfcheetah-medium-expert-v2')
   
   # Initialize agent
   agent = ReversalQLearning(
       state_dim=env.observation_space.shape[0],
       action_dim=env.action_space.shape[0],
       n_refinement_steps=8
   )
   
   # Training loop
   dataset = env.get_dataset()
   for epoch in range(100):
       loss = agent.update(dataset, batch_size=256)
       print(f"Epoch {epoch}: Loss {loss:.4f}")
   ```

3. **Evaluation:**
   ```python
   # Evaluate learned policy
   total_reward = 0
   for episode in range(10):
       obs, _ = env.reset()
       done = False
       while not done:
           action = agent.select_action(obs)
           obs, reward, terminated, truncated, _ = env.step(action)
           total_reward += reward
           done = terminated or truncated
   
   avg_return = total_reward / 10
   normalized_score = env.get_normalized_score(avg_return)
   print(f"Normalized D4RL Score: {normalized_score:.1f}")
   ```
